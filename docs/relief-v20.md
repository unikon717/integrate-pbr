# v20：覆盖修复与结构审查

本轮保持原始图案，增强色图只进行最近邻放大，保留原颜色与透明度。缓存升级为 20。

## 修改
- 门、活板门、面板及普通模型箱子进入结构检测；透明像素不再使整图退出。窗口不参与凹槽推断，家具外边界不跨边采样。
- 裂纹、雕纹允许连续斜线证据。雕纹单独调整密度上限，避免密集合法图案被整图清空；任意弯曲短线仍未普遍支持。
- 青苔砖保留石质基底，明显绿色区域采用植物参数。统计跨最多两个苔藓像素的直线证据，但不在覆盖处制造凹槽。
- 石材族可由砖、瓦、磨制等至少两类名称建立。修复单词 stone/ore 注册 ID 导致材质族学习数组越界的问题。
- 生成 COVERAGE.txt，列出未找到非原版贴图引用的对象。这些也可能只是复用了原版贴图，不全部代表漏生成；已映射对象仍可能缺少额外渲染器贴图。

## 结构性不足
1. 扫描限于普通模型 JSON 和约定盔甲路径。专用箱子、实体渲染器、自定义模型加载器需要可扩展的发现适配层。盲扫所有 entity 图片不能解决 UV 岛与资源归属。
2. 分类、结构名称分流、区域颜色判断分别决策，缺少共享的证据与置信度。建议引入 TextureContext/SurfacePlan，携带对象、模型面、UV 区域、材质族和结构依据。
3. 暗线识别不等于理解浮雕、把手或纸窗。混合材质区域仍不可靠；不能把灰木直接识别成铁。此次没有解决所有箱子五金。
4. 动画帧按尺寸猜测，任意 mcmeta 都会阻断方块增强。需要解析实际 animation 元数据，并给实体 UV 图集建立区域边界。
5. 密集检测仍有整图回退阈值，应逐步改为区域置信度回退。
6. 只有法线与反射图都缺失才可放大色图；已有其中一种图时保持原尺寸，策略仍需统一。
7. GeneratedPackManager 同时负责发现、分类、缓存、写入和重载。建议拆分生成计划与提交层，用原子版本切换减少重载时读取半批文件的风险。
8. 合成像素测试无法代替实际观感；需要跨模组真实贴图审计和游戏内固定场景对比。

## 验证
离线构建与回归通过：颜色/透明度、旋转、降噪、法线方向、门窗、斜裂纹、雕纹入口、苔藓区域、材质族学习。

自然之灵真实贴图抽查：chert_bricks、cracked_chert_bricks、chiseled_chert、mossy_travertine_bricks、cedar_door_top、cedar_door_bottom、cedar_trapdoor 均生成非零结构。

这证明进入了结构生成流程，不证明达到参考包的游戏内质量。用户判断最终观感。
