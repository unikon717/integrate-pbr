# 模型驱动的材质编译器：分支架构基线

日期：2026-09-30。状态：设计基线；已有约 153 万参数的实验网络、参考包配对数据入口及本地试训流程。训练权重尚未通过跨模组或游戏画面验收，不可称为可部署模型。

本文将本聊天分支的详细重构方案固化为后续工作的依据。新的明确用户指令优先；旧实验记录、现有启发式算法和候选模型不得悄悄改变本基线。涉及核心职责、原画保真、质量标准、下载预算的变化，先解释变化及其依据，并更新本文。实验超参数可以根据验证结果调整，记录结果即可，不必每次请求批准。

## 1. 目标与不可混淆的保证

目标链路：真实资源与上下文 → 理解对象 → 材质及结构分区 → 区域 PBR 与细节预测 → 数值约束 → LabPBR 编译 → 单一资源包。

模型承担主要视觉判断和材质生成。程序承担资源发现、执行、下载、缓存、输出约束与游戏集成。固定的材质数值上限是用户控制，不应重新演变成按名称和亮度猜结构的主生成器。

可机械保证的内容包括已识别区域的高度上限、输出格式、原颜色保真和动画布局。区域是否识别正确、反射是否自然、是否达到参考包质感，必须通过独立测试和用户验收。不得承诺未经验证的质量、速度或跨模组覆盖率。

## 2. 下载预算：目标约 1 GB 以内

为避免把依赖移出 JAR 后掩盖实际体积，默认安装采用完整必要下载量作为产品预算，目标不超过 1,000,000,000 字节。它是设计目标；超出时必须明示，不得宣称已经达标。分项预算是初始规划，可以重分配。

| 项目 | 初始预算 |
| --- | ---: |
| 默认推理权重总和 | 500 MB |
| 一种平台/后端的运行引擎及必要依赖 | 400 MB |
| 处理器、词表、配置及余量 | 100 MB |

- 所有默认必需模型累加计算，不按单文件规避预算。
- 单独报告实际下载、解压磁盘占用、峰值内存、峰值显存；下载体积不代表运行占用。
- 显卡驱动、开发训练环境、用户原贴图、生成资源包和可清理缓存不计入这项下载指标，但报告相应额外需求。
- JAR 仍以约 20 MB 为目标，重型依赖外置。
- 不打包用户不需要的多种显卡后端，不同时交付 FP32、FP16、INT8 等重复权重。
- PyTorch 适合开发原型，但如果玩家运行环境超预算，应评估紧凑的部署运行时；不得为了凑体积未经比较就量化或改变输出。

## 3. 模型方案：共享的专用多任务网络

先前的 Qwen3-VL-4B 默认语义阶段已被本节取代。玩家不应为了这个任务必需下载多十亿参数视觉语言模型。

默认候选为一个紧凑的专用 **Swin-UNet 混合网络**：卷积保留原像素与轮廓，分层窗口注意力聚合贴图上下文；共享编码器 + 小型对象上下文编码 + 图像级语义头 + 稠密材质/结构/PBR 分支。按职责分阶段，不要求部署多个大模型。先以约 10–50M 参数作为研发搜索范围，最终按效果选型，不能把参数量当作效果证明。50M 参数的 FP16 裸权重理论约 100 MB，实际文件、处理器和运行库另算。

对象语义分支分别预测**对象类型**（如工具、武器、门）和**材质组成**（如木、金属、皮革，可多选），再共同条件化稠密输出。类别不会互相替代：`wood + tool` 仍是木制工具，不因 `tool` 标签获得金属反射；金属反射必须同时通过“对象类型可信且非未知、对象组成包含金属、该像素材质分区为金属”三道条件。混合对象（如木柄金属斧头）可同时带 `wood + metal + tool`，反射只落在局部金属区域。训练和评估要单独报告两类语义及这个组合约束；对象级标签未知时应保留未知，不伪造确定标签。

如专用网络的语义能力不足，再比较小型预训练视觉编码器或轻量文本编码器。大型模型至多作为经评估的数据辅助工具，不成为默认玩家依赖；其建议须审核，不能直接作为真值。目前没有验证通过的预训练 Minecraft 材质模型。

当前代码原型起点：5 通道卷积 stem，48/64/128/192 通道分层特征，四像素窗口注意力，每层交替普通/移位窗口，三次二倍下采样；完整跳跃连接；最近邻上采样 + 深度可分卷积解码；元数据与 UTF-8 名称特征用 FiLM 条件化各尺度。窗口注意力负责上下文，原分辨率卷积分支负责单像素边缘。不能采用会直接将一像素小配件合并掉的输入 patch 尺寸。审核数据契约和训练入口已起步，已有实验检查点，但尚未验收或批准发布；确切参数量、1 GB 总下载适配度、显存和效果都需要实测。

选择 Swin-UNet 混合网络作为首个模型原型，而不是直接套用 TransUNet：门、砖缝和工具小配件要求原像素定位；Swin 的分层窗口注意力在受限的局部范围聚合上下文，卷积分支和跳连保留细边缘。常见 TransUNet 路径把卷积特征切块后交给全局 Transformer，利于远距离关系，但 token 化和全局注意力会增加计算/显存，且不自动解决边界像素的过度平滑。两者都不是质量保证。后续用完全相同的数据切分、增强、损失和指标比较小型卷积 U-Net 与当前 Swin 混合版；若跨纹理家族的 IoU、边界 F-score、深度边界误差没有可重复提升，就选择更轻方案。

Swin-UNet 值得做主原型，但不是质量结论。测试它与更小的卷积 U-Net 对照；若窗口注意力损害小纹理边界或只增加内存而无跨图案收益，保留混合 skip 路径并缩小/移除高成本阶段。没有测试前不宣称其优于卷积版本。

## 6. 资源发现与上下文契约

资源链：注册对象 → 模型/状态/渲染器 → 模型面与 UV → 当前实际贴图 → 实际资源来源。

每张纹理保存：完整资源 ID、所有 owners、资源来源、内容指纹、尺寸、动画帧布局/顺序/时间/插值、使用场景、透明模式、已知 UV 岛、染色信息、外部 PBR、发现状态。

- 不用命名空间是否等于模组 ID 作为唯一内容判断。
- 排除自身生成包，避免重复学习自己的输出。
- 正确处理父模型、状态、物品 overrides 和共享纹理。
- 动画按元数据解析，不以宽高比猜帧。
- 盔甲、箱子、自定义渲染器通过可扩展适配器发现；无法发现须报告，不能宣称完整覆盖。
- 菜单阶段未有配方/标签等数据时记为缺失；后续上下文变化纳入缓存失效，不强行读取不存在的世界。
- 纹理上下文包括名称、标签、用途、已验证家族关系、攻击与耐久等证据。武器证据不是所有像素皆金属的结论；宝石、木柄、皮革等可以共存。
- 共享贴图只有一个资源路径输出。冲突时提示影响范围；单物品独立修改需要额外重定向能力，未实现时不可承诺。

## 7. 材质、结构、区域分开表示

材质词表起点：未知、木材、石材、金属、玻璃、宝石、土壤、沙、陶瓷、织物、皮革、植物、骨质、有机物。子属性包含树皮/剥皮/加工木材、金属种类、砂浆等。表面覆盖如苔藓、油漆、锈蚀单独记录，第一版按可见表面处理。

结构词表起点：普通表面、接缝、裂纹、边框、内嵌面板、配件、树皮片、年轮、细纹、装饰图案、颗粒。材质相同不代表同一区域：两块石砖应有独立表面编号。

通过预测的像素邻接边界形成区域，并保存包含关系；不要用固定小面积阈值删掉钉子或门把手。不把普通色差自动升级为结构边界。

## 8. 模型输入输出

图像输入保留 RGB、alpha、有效像素；上下文提供对象类型、用途、材质证据、UV 和染色信息。语义预览可最近邻放大，但密集分支必须保留原像素对应关系。

输出包括：材质概率、结构概率、横纵边界、区域编号、主体深度、微细节深度、感知粗糙度、反射类别、非金属 F0、AO、可选发光/孔隙/散射、分任务风险。

训练及调试保留浮点输出与来源，最终再编码。不让模型直接输出两张无法解释的八位图。置信度须经验证校准，不采用模型自述百分比或未经校准的最大 softmax 作为质量保证。低置信度可以逐通道降级，不必抹去整张可靠结果。

## 9. 深度单位与硬约束

统一 `D = 下陷深度（alpha 单位）`，`H = 255 - D`。内部浮点，最终量化。约束作用于区域基础深度、结构变化、微细节相加后的最终输出。该单位不是固定毫米；视觉深度取决于光影及 UV。

| 对象/区域 | 约束 |
| --- | --- |
| 石砖主表面 | 最多两层平台，层差 ≤2 |
| 石砖主缝 | 以 H=255 为最高砖面时，最深 H=207，最大差 48 |
| 木门/活板门大面积平滑区域 | 区域内总高度差 ≤2 |
| 门等连续表面结构凹陷 | 总 D ≤24 |
| 连续表面普通细节层级 | 层差 ≤3；平滑区更严格的 ≤2 优先 |
| 原图确有的装饰边框 | H=255；框内 H=253 或 254 |
| 剥皮原木截面 | 单独浅层配置，明显平于普通原木；最终数值待用户视觉标定 |
| 普通原木截面 | 允许相对外缘下陷，严格保持原年轮图案 |

两层平台不包括主缝窄倒角。细节层差不是对所有邻接像素强制限坡，否则深缝会被摊成宽圆坡。边框规则不等于所有贴图外缘都抬高；结构冲突须明确优先级并报告，不可随意覆盖。

剥皮截面 2/4/6 总起伏仅为候选对比档位，不是用户已认可的最终值。砖缝 48 和平面 ≤2 等明确要求不得调参放宽。

## 10. 边缘、分辨率与细节

模型区分真实结构、颜色条纹、绘制高光/阴影和污点。训练加入暗色平面及浅色接缝反例。先预测稳定表面，再添加受预算约束的细节，禁止全图高度模糊。

原型：16→64、32→128；64 的输出可比较 128/256。分区在原像素域保留；窄倒角初始 1 输出像素（四倍输出时为 0.25 原像素），仅位于已确认的边界带。不得靠上采样凭空创造几何，不跨配件、透明轮廓、UV 岛或动画帧。

细节不能改变主缝走向、不能突破最终高度上限；平坦结果合法。输出由内容指纹与固定生成条件决定，不每次随机变化。不同分辨率的辅助图需验证实际渲染支持；如需同尺寸颜色图，仅最近邻精确放大，保持原色与轮廓。

## 11. PBR 预测与编译

粗糙度和反射独立于深度预测，不能默认越凹越粗糙或越亮越金属。内部定义感知粗糙度 rp，输出光滑度 1-rp；第三方线性粗糙度必须明确转换。

LabPBR：_n 的 RG 为 DirectX 法线 XY、B 为 AO、A 为高度；_s 的 R 为感知光滑度、G 为非金属 F0 或金属类别、B 为孔隙/散射、A 为发光。金属编码不得插值成另一个金属编号，普通 alpha 工具也不得预乘高度/发光通道。

法线从最终受约束的高度计算，横纵尺度、UV 翻转和旋转必须明确。禁止跨帧/UV 岛求梯度；平铺面与有界面采用不同边界条件。更换输出分辨率不应改变法线效果。AO 不烘入太阳方向和世界阴影。后续若加入亚像素法线细节，需独立输出及验证。

规范来源：https://shaderlabs.org/wiki/LabPBR_Material_Standard ，https://shaderlabs.org/wiki/LabPBR_Implementation_Requirements 。格式兼容不保证所有光影支持 POM、AO 等可选效果。

## 12. 物品和特殊资源

颜色 alpha 与高度 alpha 分离；透明像素不作为凹槽参与梯度。金属物品允许非零视差，不能为逃避错误全局清零。分别验证手持、GUI、掉落、穿戴。

特殊渲染路径不支持 PBR/POM 时明确记录兼容性；不能把未生效归结为模型。实体 UV 展开图不是连续平面。参考包中的真实立体模型、连接纹理和新增轮廓不属于仅靠 PBR 能复现的效果，对比之前确认来源。

## 13. 数据与标注

样本：source.png、来源/用途/许可/分组/动画信息、材质标签、结构标签、区域编号、ignore 掩码、可用目标 PBR、审核记录。允许部分标签，缺失高度不造假。参考 PBR 必须与输入空间对应；参考图重绘过年轮或砖块排列时不可直接配对。

现有生成器只辅助初标，不能充当真值。数据包括自制标准样本、可用于该训练及分发方案的成对材质、跨模组人工审核样本。明确权重与数据的来源条件，不假定不打包贴图就自动消除来源问题。

必须覆盖：暗斑非凹槽、浅缝、小配件、灰木、涂漆金属、剥皮与普通截面、苔藓、裂砖、雕纹、无配方武器、共享贴图、动画、透明、染色。

按模组/家族/原图/画风/派生关系分组划分；换色及变体不得泄漏到测试集。初试约 300 训练 +100 验证 +100 测试，只为验证方向，不保证数据足够。有效后扩大到数千张，优先补实际错误。用于调参的测试集不再视作盲测。

## 14. 训练流程

先材质/结构/边界，再参数/高度，最后联合微调。先确保分区有效，再扩大 PBR 训练。

起点：AdamW、学习率 2e-4、权重衰减 1e-2、有效批 16、5% warmup、按硬件混合精度、验证集早停。均为实验起点。

损失覆盖材质、结构、边界、平台一致性、高度/顺序、微细节、粗糙度/反射、动画一致性和辅助渲染。固定灯光渲染仅辅助，防止错误法线和粗糙度互相补偿。所有增强同步标签和法线，不加噪后沿用不匹配真值。量化/导出后必须重新评估，不用文件变小替代质量验证。

## 15. 部署与通信

Java 子进程调度；JSON 行协议走标准输入输出，日志走标准错误，大图通过任务目录文件交换。job_id、资源快照 ID、协议版本、输入、上下文、覆盖、策略与输出目录明确；结果返回状态、版本、文件/hash、检查项、回退、耗时、错误码。

支持排队、预处理、理解、分区、生成、检查、编码、完成、部分完成、跳过、失败、取消。支持能力查询、进度、取消、超时、有限重试、恢复。单张失败不破坏整批。

引擎包与模型包分版本，固定清单记录权重/预处理/词表/策略/协议和后端；断点续传、临时下载、校验、启用、回滚。玩家不临时 pip 拼环境，也不执行未审核的远端自定义模型代码。允许离线导入校验过的包。

## 16. 缓存与发布

资源重载只提取稳定快照；重型推理移到队列，不能占用资源重载屏障。后续启动复用结果，只处理变化；按需释放模型显存，用户游戏高负载时可以暂停。

指纹包含原图、动画、模型/UV、上下文、覆盖、权重、预处理、质量策略、输出格式。分层缓存语义/分区/浮点预测/最终编码；只修改深度上限时尽量复用模型结果。

临时版本完成检查后事务发布，失败保留上一完整版本，避免读取半写文件；源图变化的旧伴随图应失效，不能错配。只显示一个生成资源包。

优先级：明确用户设置 > 有效人工 PBR > 已验收模型输出 > 显示状态的保守回退。已有 _n 或 _s 时检查配套来源、尺寸和动画，不盲目补齐。区域覆盖绑定原图指纹，更新后失配需重审；共享纹理显示影响范围。

## 17. 验收和可观察性

硬检查：原画保真、帧布局、有效数值、编码、已识别区域的最终深度/层数、版本追踪。必须区分“约束正确”与“区域识别正确”。

初始发布目标（未达成）：金属精确率 ≥97%、召回 ≥90%；主缝精确率 ≥98%、召回 ≥90%；材质宏 IoU ≥85%；接受结果的硬违规为零。按类别和独立模组报告，同时报告接受/回退/跳过率，不能靠跳过难例虚增质量。

固定游戏对比控制光影版本/设置、光照/天气/时间、视角、资源包顺序；分别观察原图、旧算法、新模型和合适参考。检查凹槽、平面鼓包、油腻、反射、剥皮差异、透明边缘、动画、拼接及不同光影支持。用户决定最终视觉质量。不得自动关闭游戏。

记录实际下载、解压体积、内存、显存、单阶段耗时、首次全量与增量开销；未实测不承诺具体硬件速度。

## 18. 阶段交付与分支工作纪律

顺序：资源协议/覆盖 → 数据标注及固定测试集 → 分区模型 → PBR/约束 → 离线与游戏验收 → 运行库下载缓存 → 跨模组试运行 → 固定版本发布。每阶段先证明核心风险，再扩展范围。

优先木板、砖及变体、普通/剥皮原木、混合材质门和金属物品；随后土沙、复杂盔甲、动画和特殊渲染。范围外内容必须显式呈现。
